## Ключевое архитектурное решение: цикл interaction и снапшот состояния

**Команды делятся на два вида:**

- *мгновенные* — меняют состояние кадра и не ждут игрока: `scene`, `show`, `hide`, `music`,
  `sfx`, `set`, `jump`;
- *требующие interaction* — останавливают выполнение до действия игрока: `say`, `choice`.

Цикл движка: применять мгновенные команды подряд, пока не встретится требующая interaction;
на ней остановиться и отрисовать кадр. Один клик игрока = один `advance()` = проход до
следующей команды, требующей interaction.

Это в точности главный цикл Ren'Py (`run_context` → `Interface.interact`), тот же цикл у ink
(`Continue()` пока `canContinue`, затем `currentChoices`). Терминология взята оттуда же.

### Сейв — это снапшот, а не реплей

```ts
type SaveData = {
  version: 1;
  position: { sceneId: SceneId; step: number };
  vars: Record<VarName, VarValue>;
  stage: {
    background: BackgroundId | null;
    sprites: Array<{ tag: CharacterId; emotion: EmotionId; at: SpritePosition }>;
  };
  audio: { music: MusicId | null };
  savedAt: number;
};
```

**Загрузка:** восстановить `vars`, `stage` и `audio` из снапшота, поставить позицию, затем
выполнить **одну** команду по индексу `position.step` — она гарантированно `say` или `choice`.
Никакого проигрывания истории.

**Автосейв — в начале каждой команды, требующей interaction.** Дословно как в Ren'Py:
*«saving occurs at the start of a statement»*.

Первая редакция плана предлагала вместо этого реплей: проиграть сцену от шага 0 до
сохранённого. Разбор показал, что так не делает никто — ни Ren'Py, ни Pixi'VN, ни ink.
Реплей экономит четыре поля в сейве, но требует детерминированности всех команд и
принципиально не восстанавливает путь исполнения: после `jump` из середины другой сцены
проигрывать нечего. Документация Ren'Py про это прямо: *«Ren'Py only saves the current
statement, and the statement it needs to return to. It doesn't remember how it got there»*.

**Бонусы снапшота:** `stage` — plain data в несколько полей, поэтому rollback на реплику
назад позже стоит просто «держать N последних снапшотов», а лог диалога — «держать
прочитанные реплики». Оба пункта из списка «не в 0.1» становятся почти бесплатными.

**Цена:** сейв вырос с 4 полей до 6. Поле `position` сделано объектом, чтобы позже принять
`callStack`, когда появятся вызываемые подсцены (у Ren'Py стек вызовов лежит в сейве).

### Переменные объявляются с дефолтами

```ts
export const variableDefaults = { metAnna: false, trust: 0 } as const;
type VarName = keyof typeof variableDefaults;
```

При загрузке: `{ ...variableDefaults, ...save.vars }`. Старый сейв, сделанный до появления
новой переменной, не ломает игру — переменная получит дефолт.

Это механика `default` из Ren'Py, где рекомендация звучит буквально: *«It is highly
recommended to `default` every variable in your game that is susceptible to change»*.
Заодно это закрывает миграцию сейвов, для которой раньше было только поле `version`.

## Структура репозитория

```
src/
  app/        точка входа, ThemeProvider, RootStoreProvider, глобальные стили, горячие клавиши
  pages/      MainMenuPage, GamePage
  widgets/    Stage (композиция кадра), DialogueBox, SettingsOverlay
  features/   advance-dialogue, make-choice, save-game, load-game, change-settings
  entities/   background (ui + карта ассетов), character (ui + карта ассетов), save-slot
  shared/     ui (Button, Slider), lib (useStageScale, useTypewriter), config, types

  engine/     content-types, interpreter, navigation, save, audio
  content/    ids, variableDefaults, scenes, демо-сцена, __dev__/ ветвящийся тестовый контент
  assets/     backgrounds/, characters/, music/, sfx/
```

**Правила границ** (соблюдаем руками, без линтера):

- `engine/` не импортирует ничего из FSD-слоёв и не знает о `content/`. Реестр сцен
  передаётся в интерпретатор снаружи, при инициализации приложения.
- `engine/` не содержит React. Реакт-обвязка живёт в `app/providers`.
- FSD-слои импортируют `engine/` свободно, но только вниз по своим слоям
  (`pages → widgets → features → entities → shared`).
- О сюжете знает только `content/`.

Это то же разделение, что у Ren'Py между execution-слоем и display-слоем: исполнение меняет
логическое описание кадра, отрисовка отдельно превращает его в пиксели.

`engine/` пока остаётся на верхнем уровне, а не в `shared/`.

## Типы контента

```ts
type SpritePosition = 'left' | 'center' | 'right';
type LocalizedText = string | { $key: string };

type Command =
  // мгновенные
  | { type: 'scene'; background: BackgroundId }
  | { type: 'show'; tag: CharacterId; emotion: EmotionId; at?: SpritePosition }
  | { type: 'hide'; tag: CharacterId }
  | { type: 'music'; asset: MusicId | null; ifChanged?: boolean }
  | { type: 'sfx'; asset: SfxId }
  | { type: 'set'; name: VarName; value: VarValue }
  | { type: 'jump'; scene: SceneId }
  // требуют interaction
  | { type: 'say'; speaker: SpeakerId; text: LocalizedText }
  | { type: 'choice'; options: ChoiceOption[] };
```

Четыре конвенции, взятые у Ren'Py:

1. **`scene` очищает кадр и ставит фон, `show` добавляет спрайт поверх.** Раньше в плане была
   одна команда `background`, которая смешивала эти операции.
2. **Автозамена по тегу.** `show anna sad` заменяет ранее показанную `anna` — персонаж
   опознаётся тегом, а не полным именем ассета. Поэтому смена эмоции не требует `hide`, и
   `hide` вообще нужен редко.
3. **Позиции — фиксированный набор `left / center / right`**, а не пиксели. Это `at left`
   из Ren'Py; пиксельные координаты в контенте — путь к тому, что арт нельзя заменить.
4. **`ifChanged` у музыки** — не перезапускать трек, если он уже играет. Критично при
   загрузке сейва внутри той же сцены: иначе музыка дёрнется с начала.

Плюс два приёма для автокомплита:

- `BackgroundId`, `CharacterId`, `MusicId` выводятся из реестров ассетов
  (`keyof typeof backgrounds`) — опечатка в имени файла становится ошибкой компиляции;
- `LocalizedText` допускает и строку, и ключ; движок достаёт текст через `resolveText()`,
  который в 0.1 просто возвращает строку.

## Сторы

| Стор | Что держит | В сейве |
|---|---|---|
| `GameStore` | `position`, `vars` | да |
| `StageStore` | фон, спрайты (тег, эмоция, позиция) | да |
| `DialogueStore` | текущая реплика, варианты выбора, `isRevealing` | нет — выводится из команды на `position.step` |
| `SettingsStore` | громкости по каналам, скорость текста | да, отдельным ключом |
| `UiStore` | активный экран, открыт ли оверлей настроек | нет |
| `AudioService` | howler, текущий трек | нет, не observable |

Три независимых хранилища, как в Ren'Py: сейв (точка в игре), настройки (переживают все
прохождения), и — позже — `persistent` для прочитанных реплик и достижений.

## Этапы

Каждый этап заканчивается остановкой: ты запускаешь и смотришь, я не иду дальше без
подтверждения. Коммит — по этапу.

Ниже — краткое описание. Подробные шаги, критерии готовности и открытые вопросы по каждому
этапу лежат отдельными файлами в [tasks/](./tasks/).

### Этап 0. Инициализация проекта · [задача](./tasks/00-setup.md)

- Scaffold Vite `react-ts`. В каталоге уже лежат `README.md` и `.claude/`, а `npm create vite`
  на непустой папке спрашивает подтверждение в интерактиве — поэтому генерирую в temp и
  переношу файлы, ничего существующего не затрагивая.
- Зависимости: `react`, `react-dom`, `mobx`, `mobx-react-lite`, `styled-components`.
  Dev: `typescript`, `vite`, `@vitejs/plugin-react`, `eslint` + `typescript-eslint` +
  `eslint-plugin-react-hooks`, `prettier` + `eslint-config-prettier`, `vitest`,
  `babel-plugin-styled-components`. `zod` и `howler` ставятся на этапах 5 и 6 — там, где
  реально нужны.
- `tsconfig`: `strict`, `noUncheckedIndexedAccess` (движок постоянно ходит по массиву команд
  по индексу — здесь это ловит реальные баги), алиас `@/*` → `src/*`.
- Скрипты: `dev`, `build`, `preview`, `lint`, `format`, `typecheck`, `test`.
- `.gitignore`, переписанный `README.md` (заодно убираю лишние кавычки в заголовке),
  `CLAUDE.md` с командами и конвенциями проекта.

**Проверить сразу, до всего остального:** совместимость `styled-components` с той версией
React, которую поставит шаблон Vite. Если вылезет конфликт peer-зависимостей — фиксируем
React 18, это дешевле, чем воевать со стилями.

Готово, когда: `npm run dev` открывает страницу, `lint`, `typecheck`, `test`, `build` проходят.

### Этап 1. Каркас: кадр, тема, экраны · [задача](./tasks/01-shell.md)

- Тема: цвета, шрифты, z-индексы, длительности анимаций. Плюс токены, специфичные для
  новеллы — их список подсказал `gui.rpy` из Ren'Py: высота диалогового окна, позиция реплики,
  позиция и размер имени говорящего отдельно от размера реплики, отступы вариантов выбора.
- Глобальные стили: reset, чёрный фон под letterbox, запрет выделения текста там, где оно
  мешает клику.
- `Stage`: контейнер 1920×1080, `transform: scale(min(vw/1920, vh/1080))` через
  `useStageScale` на `ResizeObserver`. Слои кадра: фон → спрайты → UI → оверлей.
- Корневой стор + провайдер + `useStores()`.
- `MainMenuPage` («Новая игра», «Продолжить» пока неактивна) → `GamePage` с пустой сценой.

Готово, когда: меню открывается, «Новая игра» ведёт на пустой кадр 16:9, ресайз и
фуллскрин не ломают пропорции.

### Этап 2. Ядро движка: типы и интерпретатор · [задача](./tasks/02-engine-core.md)

- `engine/content-types`: команды, сцена, `LocalizedText`, `resolveText`.
- `engine/interpreter`: цикл до команды, требующей interaction; применение мгновенных команд к
  `StageStore` с автозаменой по тегу; `scene` очищает спрайты; `start()`, `advance()`,
  `requestAdvance()`.
- `engine/navigation`: реестр сцен, `jump`.
- `content/`: реестры id, `variableDefaults`, демо-сцена с текстом-заглушкой.
- Тесты Vitest: мгновенные команды применяются подряд; на команде с interaction выполнение
  встаёт; `show` с тем же тегом заменяет спрайт, а не добавляет второй; `scene` очищает
  спрайты; `jump` переключает сцену; снапшот состояния сериализуется и восстанавливается
  без потерь.

Готово, когда: `npm test` зелёный. Визуально на этом этапе ещё ничего нового — проверка
тестами, это осознанно.

### Этап 3. Рендер сцены — первый играбельный билд · [задача](./tasks/03-rendering.md)

- `entities/background`, `entities/character` — слои и карты ассетов; позиции спрайтов
  `left / center / right`.
- `widgets/dialogue-box` — имя говорящего, текст, кнопка Next, typewriter через
  `useTypewriter`. Реплика с самого начала занимает финальную высоту, чтобы окно не дёргалось
  по мере набора текста — приём тега `{done}` из Ren'Py.
- `features/advance-dialogue` — клик и клавиши идут в **один** `requestAdvance()`: если текст
  ещё печатается — дописать мгновенно, если дописан — следующий шаг.
- Горячие клавиши: Space / Enter — дальше, Esc — меню. Один обработчик в `app/`.
- Плейсхолдеры: 2 фона и персонаж с 3 эмоциями — SVG-градиенты и силуэты. Намеренно
  некрасивые, чтобы их хотелось заменить.

Готово, когда: линейная сцена проходится от начала до конца мышью и с клавиатуры, текст
печатается, скип работает.

### Этап 4. Выборы, переменные, переход между сценами · [задача](./tasks/04-choices.md)

- `features/make-choice` + рендер вариантов, команда `set`, опциональное условие `when`
  у варианта выбора.
- Реестр `variableDefaults` подключён: движок стартует с дефолтов, `set` их меняет.
- Ветвящийся тестовый контент в `content/__dev__/` — в игру не входит, нужен чтобы прогнать
  механику, которой в линейной сцене нет.
- Тесты: выбор ведёт в нужную ветку, переменная влияет на доступность варианта.

Готово, когда: dev-сцена с ветвлением проходится оба раза по-разному.

### Этап 5. Save / Load · [задача](./tasks/05-save-load.md)

- `engine/save`: снапшот по схеме выше, ключ в localStorage, `zod`-схема на валидацию
  загруженного (кривой сейв прошлой версии не должен ронять игру), слияние с
  `variableDefaults`, миграция по `version`.
- Загрузка: восстановить снапшот → выполнить одну команду на `position.step`.
- Автосейв в начале каждой команды, требующей interaction. Один слот.
- «Продолжить» в меню активна, когда сейв есть.
- Тесты: сохранение → загрузка даёт то же состояние; сейв без новой переменной получает её
  дефолт; сейв с мусором отбрасывается, а не ломает игру.

Готово, когда: пройти половину сцены, обновить страницу, «Продолжить» — то же место, тот же
фон, тот же персонаж в той же эмоции и позиции.

### Этап 6. Аудио и настройки · [задача](./tasks/06-audio-settings.md)

- `engine/audio` поверх **howler.js**: каналы `music` и `sound` (разделение из Ren'Py),
  fade in/out, `ifChanged`. Howler сам разбирается с autoplay-политикой браузера — ручная
  очередь на первый жест игрока, которая планировалась раньше, не нужна.
- `SettingsStore` + оверлей по Esc: громкость по каналам, скорость текста в символах в
  секунду; хранится отдельным ключом от сейва.

Готово, когда: музыка играет и не падает на политике автоплея, загрузка сейва внутри той же
сцены не перезапускает трек, ползунки влияют на звук и скорость печати немедленно.

### Этап 7. Полировка и сдача 0.1 · [задача](./tasks/07-polish.md)

- Fade-переход между сценами. Изменения кадра накапливаются и показываются одним переходом —
  как `show` в Ren'Py, который сам по себе не вызывает отрисовку. Длительность по умолчанию
  0.5 с, это стандарт жанра.
- Актуализация `README.md` и `CLAUDE.md`.
- Прогон `lint` / `typecheck` / `test` / `build`.
- Ревизия: что оказалось неудобным, что переносим в 0.2.

## Решения, принятые без отдельного вопроса

1. **Автосейв одного слота уже в 0.1.** Бриф относит автосейв в будущее, но кнопке
   «Продолжить» нужен хоть один сейв. Разбор показал, что автосейв на каждой команде с
   interaction — это ровно поведение Ren'Py, так что решение совпало со стандартом.
   Множественные слоты остаются в будущем.
2. **Плейсхолдер музыки** — короткий сгенерированный WAV-луп, чтобы аудио-система была на
   чём проверена.
3. **Fade-переход попал в 0.1** (этап 7). Единственная анимация.
4. **`noUncheckedIndexedAccess`** включён.
5. **`CLAUDE.md`** создаётся на этапе 0: команды, конвенции, правила границ слоёв.
6. **Язык кода** — английский: имена, коммиты, комментарии. Русский только в тексте игры и
   в документах в `.claude/`.
7. **Канал `sfx` есть в типах, но в контенте 0.1 не используется.** Добавить канал в howler
   сразу дешевле, чем переделывать аудио-слой под второй канал потом.

## Риски

- **Резкость текста при `transform: scale`.** На нецелых коэффициентах текст может выглядеть
  чуть мягче. Альтернатива — верстать внутренности в единицах контейнера (`cqw`). Решаем по
  факту, на этапе 1.
- **styled-components и свежий React.** Возможен конфликт peer-зависимостей; проверяем
  первым делом на этапе 0, откат — на React 18.

  редкие. Если упрёмся — слой `engine/audio` изолирует её, и переезд на Web Audio API
  затронет один файл. Это и есть причина не звать howler напрямую из UI.

  соблазнов — контексты, NVL-режим, система screens, дельты в rollback. Всё это осознанно
  отброшено, см. [engine-research.md](./engine-research.md).
