# Этап 3. Рендер сцены — первый играбельный билд

**Цель:** линейная сцена проходится от начала до конца мышью и с клавиатуры, текст печатается,
клик доводит реплику мгновенно. Это точка «оно живое».

**Зависимости:** [этап 1](./01-shell.md), [этап 2](./02-engine-core.md).
**Контекст:** [plan-0.1.md → Этап 3](../plan-0.1.md)

---

## Шаги

### 1. `entities/background`

- `BackgroundLayer` — читает `StageStore.background`, рисует ассет по карте
- карта `BackgroundId → файл`
- слой всегда занимает весь кадр 1920×1080, без `cover`/`contain` фокусов: арт рисуется под
  ровно это разрешение

### 2. `entities/character`

- `CharacterSprite` — тег, эмоция, позиция
- карта `тег → эмоция → файл`
- позиции `left / center / right` берутся из токенов темы, не из пикселей в контенте.
  Это `at left` из Ren'Py: пиксельные координаты в сценарии означают, что арт нельзя заменить
  без правки контента
- порядок отрисовки: в порядке массива `sprites`

### 3. `widgets/dialogue-box`

- имя говорящего (свой размер и цвет из токенов), текст реплики, кнопка Next
- **реплика с самого начала занимает финальную высоту** — приём тега `{done}` из Ren'Py:
  иначе окно дёргается по мере набора текста. Реализация: невидимая копия полного текста
  задаёт высоту, видимая печатается поверх
- нарратив (без говорящего) — без плашки имени

### 4. `shared/lib/useTypewriter`

- вход: полный текст, скорость в символах в секунду
- выход: видимая часть, флаг `isRevealing`, метод `finish()` для мгновенного доведения
- корректная уборка таймера при смене реплики и при размонтировании
- скорость берётся из настроек (этап 6), пока — из токенов темы

### 5. `features/advance-dialogue`

Единственная точка продвижения — `requestAdvance()`:

```
если isRevealing: finish()      // клик доводит текст
иначе:            advance()     // следующий шаг
```

Клик и клавиши идут **в неё же**. Никакого дублирования логики: это то, из-за чего оба
пункта — typewriter и хоткеи — попали в один этап.

### 6. Горячие клавиши

- Space и Enter — `requestAdvance()`, Esc — меню
- один обработчик в `app/`, не по компонентам
- **гасить автоповтор клавиши** при удержании: иначе зажатый Space превращается в
  неуправляемый skip через всю сцену

### 7. Плейсхолдеры

- 2 фона: SVG-градиенты, 1920×1080
- 1 персонаж, 3 эмоции: SVG-силуэты, различимые между собой
- намеренно некрасивые, чтобы хотелось заменить

### 8. Демо-сцена

Довести линейную сцену из этапа 2 до осмысленного прохода: смена фона, появление персонажа,
смена эмоции, несколько реплик, нарратив.

## Открытые вопросы

- [ ] **(квиз, решить до начала)** Клик в любом месте кадра продвигает диалог, или только
      кнопка Next? В жанре стандарт — клик по всему экрану, кнопка при этом остаётся
      подсказкой. Но тогда клики по вариантам выбора и по кнопкам меню должны надёжно
      останавливать всплытие, иначе выбор варианта заодно продвинет диалог. Влияет на
      разметку слоёв, поэтому вопрос заранее.
- [ ] **(доки)** Проверить по документации Ren'Py и статьям про UI новелл, как принято
      разводить «клик по кадру» и `quick_menu` вдоль нижнего края, чтобы не конфликтовали.
- [ ] **(доки)** Поведение при удержании Space. В жанре есть отдельный skip на Ctrl —
      выяснить, ожидается ли от Space skip-по-удержанию, или его принято гасить. Пока
      исхожу из «гасить», skip в 0.1 не входит.
- [ ] **(по факту)** `requestAnimationFrame` или `setInterval` для typewriter. rAF даёт
      ровный ход при любой скорости и сам замирает в неактивной вкладке; интервал проще.
      Решу на реализации, результат записать сюда.
- [ ] **(по факту)** Предзагрузка ассетов. При первой смене фона возможно мигание. Проверить
      на плейсхолдерах, и если видно — предзагружать фоны сцены при её старте.
- [ ] **(квиз)** Показывать ли кнопку Next визуально, если клик работает по всему кадру.
      Обычно показывают маленький индикатор «click to continue» в углу окна.
