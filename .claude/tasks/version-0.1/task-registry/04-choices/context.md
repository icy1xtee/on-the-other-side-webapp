# Этап 4. Выборы, переменные, переходы — контекст

Исходная спецификация — [../../04-choices.md](../../04-choices.md). Ход работ —
[progress.md](./progress.md).

---

## Цель

Ветвление работает: игрок выбирает вариант, блок-реакция играет и возвращается за развилку,
`goTo` уводит в другую сцену, переменные решают, какие варианты видны. Проверяется на
dev-контенте — игровая демо-сцена остаётся линейной.

## Опирается на

- **Этап 2** — типы `choice` / `ChoiceOption` с блоками, разворот блоков в плоскую программу
  (`compileScene`), `available` по `when`, переменные с дефолтами и `set`.
- **Этап 3** — панель реплики, печать текста, `requestAdvance`, отсечение кликов по кнопкам
  (`isSystemControl`), `PillButton`, резиновая вёрстка (`u()`), локализация.

## Что уже было до этапа

Спецификация писалась до этапа 2, и часть её уже сделана там: переменные стартуют с
`variableDefaults`, `set` их меняет, блоки выбора разворачиваются, `available` считается.
На этап остались: выбор варианта, подпись к выбору, UI, dev-контент.

## Решения

| Решение | Суть | Чьё |
|---|---|---|
| Панель во время выбора | **Подпись у выбора**, как реплика внутри `menu` в Ren'Py: `choice(say('mila', 'Куда пойдём?'), [...])` или `choice(narrate('…'), [...])`. Подпись — часть команды `choice`, а не «предыдущая реплика», поэтому сейв на развилке (этап 5) покажет её же | Павел |
| Вид вариантов | ~~Колонка кнопок по центру сцены~~ — Павлу не понравилось. **Текстовые строки в панели под подписью**: обычный текст, при наведении или фокусе «загорается» (цвет логотипа, свечение, точка-маркер в отступе панели). Прочитанная подпись отступает: приподнимается, тускнеет до 0.5, обрезается до одной строки с многоточием; если обрезана — полный текст в тёмно-сером тултипе по наведению. Без подписи варианты стоят на месте текста | Павел |
| Когда появляются варианты | **Когда игрок прочитал подпись**: она печатается как обычная реплика, с кареткой; клик во время печати её допечатывает, следующий клик (или Space/Enter) — показывает варианты, подпись сворачивается. Допечатавшаяся сама подпись тоже ждёт клика. Состояние «подпись прочитана» — в `useAdvanceDialogue`, по ключу реплики. Иначе, чем в Ren'Py (там варианты сразу), — решение Павла после прогона | Павел |
| Ключ реплики | `GameStore.line.key` — `сцена:шаг:номер показа`. Номер растёт с каждым показом, поэтому возврат сюжета на тот же шаг (цикл «спросить ещё раз») заново печатает реплику и заново ждёт прочтения подписи | по факту |
| Ширина текста | Текст и свёрнутая подпись — на всю ширину панели: кнопки в углу над первой строкой, места не занимают. `textMaxWidth` 1120 = вся внутренняя ширина при 16:9; на окнах шире строка дальше не растёт. Тултип обрезанной подписи — по ширине текста, но не шире подписи: дальше текст переносится (`align="start"`) | Павел |
| Случайный клик | Варианты появляются в панели — там, куда игрок только что кликал, листая реплики. Пока вариант въезжает (первая половина анимации), он не кликается: `pointer-events: none` в начальном кадре анимации. Проверено CDP: клик в момент появления ничего не выбирает | по факту |
| Системные кнопки | **Иконки Lucide с тултипами** (просьба Павла): Авто — `Play`, Пропуск — `FastForward`, История — `ScrollText`, Сохранить — `Save`, Загрузить — `FolderOpen`, Выборы — `Signpost`. Тултип — `shared/ui/Tooltip` (чистый CSS, задержка 250 мс), кнопка — `shared/ui/IconButton` (`label` = `aria-label` = текст тултипа). Шестерёнка в шапке — тоже `IconButton`, тултип снизу. У заблокированной: «Выборы — пока недоступно». Стоят в правом верхнем углу панели, от краёв — на том же расстоянии, что друг от друга (`button.gap`) | Павел |
| Плашка говорящего | **Имя и портрет — на отдельной плашке поверх верхнего края панели**, наполовину снаружи, с прежним отступом слева (`namebox` в теме, термин Ren'Py). Отступ сверху панели одинаков с плашкой и без: текст реплики **всегда начинается в одной точке** — у рассказчика, у голоса без портрета и у персонажа | Павел |
| Портрет | Портрет из дизайна — фигурка в полный рост 75×134, на аватаре 44 px лица не видно. Заменён **лицом, вырезанным из спрайта Милы** (192×192, WebP, 19.6 КБ) | по факту |
| Высота панели | Три строки текста (`dialogue.minLines`): реплика в две строки или подпись + два варианта помещаются без роста панели. Больше вариантов — панель растёт вверх | по факту |
| Запуск dev-контента | **Параметр в URL**, только на dev-сервере: `?dev=branching`. В прод-сборку dev-сцены не попадают (проверено по `dist`) | Павел |
| Ритм | Этап **одним заходом**, спорные моменты — в реестр к ревью | Павел |
| Недоступный вариант | Скрывается (решение ревью этапа 2). Движок отдаёт все варианты с `available`, `GameStore.choiceOptions` оставляет доступные, но с исходным индексом — его и принимает `choose` | ревью этапа 2 |
| Все варианты недоступны | Выбор **пропускается**, выполнение идёт за развилку — как Ren'Py: *«If the `if` condition is not met for any choice, the menu is skipped»*. Для этого у скомпилированного `choice` есть `next` | Ren'Py |
| `choose` | `choose(state, registry, index)` — индекс среди всех вариантов; заново проверяет `when`; на скрытый или несуществующий вариант, или не на развилке — `EngineError` | по факту |
| Формат `when` | Остаётся функцией-предикатом: в сейв попадают только значения переменных, условия не сериализуются | по факту |
| Клик и клавиши на развилке | Клик по сцене и Space/Enter только допечатывают подпись; пропустить выбор нельзя (`GameStore.advance` игнорирует не-реплику). Вариант — кнопка: клик по нему не продвигает диалог, Tab + Enter выбирают с клавиатуры | по факту |
| Каретка | На развилке не показывается: она значит «клик — дальше», а здесь нужно выбрать | по факту |
| Dev-сцены и типы | Фабрики сюжета разрешают `goTo` только в сцены игры. В `content/__dev__/dsl.ts` свои `goTo`, `choice`, `option` с id dev-сцен; остальные фабрики — общие | по факту |
| Dev-сцены и перевод | Только русский, в проверку переводов не входят; на английском показывается русский оригинал | по факту |

## Что вошло

- `engine/`: `ChoicePrompt` и `prompt` у `choice`; `next` у скомпилированного `choice`;
  `choose()`; пропуск выбора без доступных вариантов; тесты; README.
- `GameStore`: `line` отдаёт и подпись выбора; `choiceOptions` (доступные варианты с
  индексами); `choose(index)`; тесты.
- `content/`: `say` / `narrate` возвращают `Line`; `choice` принимает подпись первым
  аргументом; `collectStoryText` собирает подписи; тесты фабрик.
- `content/__dev__/` — `dsl.ts`, `branching.ts` (сцены `branching` → `branchingStreet` /
  `branchingHome`), `index.ts`, `branching.test.ts` — проход тремя путями.
- `features/make-choice/ChoiceList.tsx`; `DialogueBox` — слот `choice`, плашка `Namebox`,
  отступающая подпись `Prompt`, кнопки-иконки; `GamePage` — варианты в панели; токены
  `namebox`, `choice`, `tooltip` и цвета в теме.
- `shared/ui/Tooltip.tsx`, `shared/ui/IconButton.tsx`, `shared/lib/useIsTruncated.ts`;
  шестерёнка в шапке — `IconButton`; ключ `dialogue.locked` — «{{action}} — пока недоступно».
- `assets/portraits/mila.webp` — лицо из спрайта вместо фигурки из дизайна.
- `main.tsx` — `?dev=<сцена>` на dev-сервере.

## Что не вошло

- История выборов (кнопка «Выборы») — заблокирована, вне 0.1.
- Горячие клавиши 1–9 для вариантов.
- Выбор в игровой демо-сцене — по плану сюжет 0.1 линейный.
- Дизайн экрана выбора из Claude Design — пока черновик.
