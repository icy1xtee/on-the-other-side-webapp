# Этап 1. Фундамент

**Цель:** до новых функций подготовить три вещи — демо, на котором их можно проверить,
страховку из e2e-тестов и CI, и сторы, которые эти функции выдержат.

**Зависимости:** [этап 0](./00-design.md).
**Ветка:** `feat/0.2-stage-1-foundation`
**Контекст:** [plan-0.2.md → решения 1, 3, 4](../../plan-0.2.md); ретроспектива 0.1 —
[журнал 0.1](../version-0.1/progress.md).

---

## Шаги

Порядок важен. e2e-тесты идут **до** рефакторинга, чтобы страховать разделение стора.

### 1. CI

- GitHub Actions запускается на PR в `main` и на push в `main`.
- Node берётся из `.nvmrc`, затем `npm ci`, `lint`, `typecheck`, `test`, `format:check`,
  `build`. Кеш npm.
- e2e добавляется отдельной задачей на шаге 3.

### 2. Расширенное демо (решение 1)

- **Объём:** 30–40 реплик в 2–3 сценах. У каждой сцены есть название (этап 0, шаг 8).
- **Развилка:** одна, на 2–3 варианта. Ветки — блоки `then` у вариантов или свои короткие
  сцены. Сходятся они через `goTo` в общую сцену. Выбор пишется в переменную (`set`).
- **Текст:** заглушки в тоне примеров из макетов — дождь, тишина, «зовут с другой стороны».
  Места — те, на которые есть арт: комната и улица. Персонажи — Мила и голос за дверью.
- **Звуки:** места для звуков отмечены командой `sfx` (дверь, шаги); играть они начнут на
  этапе 6.
- **Перевод** на английский — полный: `translations.test` пуст.
- **Для чего демо дальше:** длина — Auto и History; повторное прохождение — Skip; развилка —
  откат с другим выбором; несколько мест для сейва — слоты.

### 3. e2e smoke-тесты (решение 3)

- **Инструмент:** Playwright, только Chromium.
- **Против чего гоняем:** прод-сборка через `vite preview`, чтобы ловить и поломки сборки.
- **Сценарии:**
  1. «Новая игра» → прохождение до конца → главное меню.
  2. Развилка: выбор кликом и цифрой уводит в свою ветку.
  3. Реплика → перезагрузка страницы → «Продолжить» возвращает на ту же реплику.
- **Скорость:** до старта в `ots:settings` кладётся мгновенный текст, чтобы не ждать печать.
- **Как проверяем:** по тексту и ролям (`getByRole`, `getByText`), не по пикселям.
- **Запуск:** `npm run e2e` — сборка, preview и тесты. В CI — отдельная задача.
- **Свой TS-проект** под e2e — `tsconfig.e2e.json` в `tsc -b`, oxlint покрывает и его.
- **CLAUDE.md:** правило «UI не тестируется» становится «UI проверяют e2e основных путей».

### 4. Разделение `GameStore` (ретроспектива 0.1)

Сейчас в одном классе живут четыре вещи:
- игровой цикл: `state`, `interaction`, `turn`, `advance` / `choose`;
- представление: `background`, `sprites`, `line`, `choiceOptions` — ids превращаются в URL и
  имена;
- проигрывание аудио-эффектов;
- автосейв и «Продолжить».

Предложение, уточнить на этапе:
- **цикл** — `GameStore`;
- **сейвы** — отдельный стор: автосейв, `resumable`, чтение и запись, `onSaveUnavailable`, время
  игры. На этапе 4 к нему добавятся слоты;
- **представление** — чистые функции, которые из состояния и `presentation` дают кадр и
  реплику. Их тестируют без стора;
- **аудио-эффекты** — рядом с циклом, отдельной функцией.

Учесть, что придёт дальше: журнал и стек отката (этап 3) — рядом с циклом, Auto и Skip (этап 2)
— в состоянии чтения (шаг 5).

Поведение не меняется: тесты `GameStore.test.ts` разносятся по новым модулям и проходят, e2e
зелёные.

### 5. Состояние чтения — в стор (ретроспектива 0.1)

- **Сейчас** в `useAdvanceDialogue` живут печать (`useTypewriter`), «вопрос прочитан»
  (`readPrompt`) и `requestAdvance`.
- **Переезжает в стор:**
  - какая реплика на экране, допечатана ли она, прочитан ли вопрос развилки;
  - команды `requestAdvance()` и `finishLine()`.
- **Таймер печати** (rAF) остаётся в UI, но:
  - стор узнаёт, что реплика допечатана — это нужно Auto;
  - стор может велеть показать её сразу — это нужно Skip и откату.
- **Хук становится тонким:** переводит клики и клавиши в команды стора.
- **Тесты** на стор чтения: допечатка, вопрос развилки, цифры 1–9.

## Открытые вопросы

- [x] **(доки)** GitHub Actions: актуальные версии `checkout` и `setup-node`,
      `node-version-file: .nvmrc` и `engine-strict` в CI.
      → `checkout@v7`, `setup-node@v7` с `node-version-file: .nvmrc` и `cache: npm`; в
      `.nvmrc` точная версия, `engine-strict` доволен.
- [x] **(доки)** Playwright:
      - `webServer` против `vite preview`;
      - установка одного Chromium;
      - кеш браузера в CI;
      - TS-проект для e2e.

      → `vite preview` на своём порту 4180; в CI `install --with-deps --only-shell chromium`;
      браузер не кешируем — Playwright не советует; `tsconfig.e2e.json` в `tsc -b`.
- [x] **(по факту)** Как именно делится `GameStore` — записать в `context.md` этапа.
      → цикл — `GameStore`, сейвы и время игры — `SaveStore`, виды — `presentation.ts`, аудио —
      `audioEffects.ts` ([реестр](./task-registry/01-foundation/context.md)).
- [x] **(по факту)** Как стор чтения узнаёт, что реплика допечатана: считает по времени и
      скорости (чистая функция в `typewriter.ts`) или UI сообщает о конце печати.
      → UI сообщает (`onTyped`): машинка остаётся единственным источником времени; мгновенный
      текст стор знает из настроек.
