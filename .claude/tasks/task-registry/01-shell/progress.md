- `RootStore` создаётся в `main.tsx`, а не в `useState` внутри `App`: StrictMode и Fast
  Refresh его не пересоздают, и он единственный.
- В `Screens` — `switch` по `ui.screen`: TypeScript проверяет, что все экраны обработаны.

### 2026-10-09 · шаг 3 — масштабируемый кадр · закоммичен `646b8d9`

**Сделано:**

- `shared/config/stage.ts` — `MIN_STAGE_SCALE = 0.5`.
- `shared/lib/stageScale.ts` — `fitStage(w, h, dpr)` → `{ scale, offsetX, offsetY }`,
  смещения округлены до физического пикселя. +4 теста (центрирование по обеим осям, привязка
  к пикселю при dpr 1 / 2 / 1.25), всего 7.
- `shared/lib/useStageFit.ts` — хук: `ResizeObserver` на контейнере, первый замер в
  `useLayoutEffect` до отрисовки, чтобы кадр не мелькал без масштаба.
- `widgets/stage/Stage.tsx` — `Viewport` (`fixed`, `inset: 0`, letterbox) → `Frame` 1920×1080
  с `translate(...) scale(...)` → четыре слоя-слота `background / sprites / ui / overlay` по
  `theme.zIndex`. При `scale < 0.5` вместо кадра — заглушка «Окно слишком маленькое».
  `data-scale` на кадре — для отладки в devtools.
- `App` — временная отладочная разметка в слое `ui`: пунктир по краям кадра, абзац русского
  текста размером реплики. Уйдёт на шаге 4.

**Проверено:** `lint`, `typecheck`, `test` (7), `format:check`, `build`. Скриншоты headless
Chrome: 1920×1080 → `scale(1)`, смещение 0; 1210×680 → `scale(0.62963)`, текст резкий;
4:3 и 21:9 — кадр по центру с полосами; 900×500 и 600×1000 — заглушка. Класс кадра в DOM —
`Stage__Frame-…`, значит displayName от Oxc работает. Попутно: у headless Chrome область
страницы на 18×130 px меньше `--window-size` — учтено при съёмке.

**Проверить глазами:** фуллскрин (F11), быстрый ресайз мышью — кадр не прыгает и не мерцает;
резкость текста на твоём мониторе (особенно если масштаб Windows 125%/150%); сжать окно
меньше 960×540 — заглушка, обратно — кадр.

**Решения по ходу (мелкие, обратимые):**

- Хук назван `useStageFit`, а не `useStageScale` из спецификации: он отдаёт масштаб и
  смещение, не только масштаб.
- `layers.ts` из спецификации не понадобился: имя слоя — `keyof theme.zIndex`, порядок слоёв
  живёт в теме.
- Слои — слоты-пропсы `Stage` (`background`, `sprites`, `ui`, `overlay`): этап 3 просто
  передаст в них компоненты.
- Слои `pointer-events: none`, их дети — `auto`: пустой верхний слой не перехватывает клики
  нижних.
- `transform` — инлайн-стилем, а не пропсом styled-components: иначе на каждый ресайз
  генерировался бы новый CSS-класс.
- Узкое вертикальное окно всегда уходит в заглушку: ширина меньше 960. Это прямое следствие
  порога, отдельной логики нет.

**Проверено:** `lint`, `typecheck`, `test`, `format:check`, `build` — проходят. Временный файл

**Проверить глазами:** `npm run dev` — заголовок «On the Other Side» набран системным шрифтом

**Решения по ходу (мелкие, обратимые):**

- Тип темы выводится из объекта (`typeof theme`), а не описывается отдельным интерфейсом —
  структура в одном месте, дизайн меняет только значения.
- Черновая геометрия диалога и выборов — дефолты `gui.rpy` Ren'Py для 1920×1080
  (`textbox_height 278`, `name_xpos 360`, `dialogue_xpos 402`, `dialogue_ypos 75`,
  `dialogue_width 1116`, `choice_button_width 1185`, `choice_spacing 33`, размеры текста
  33 / 45).
- Размеры — числа в px макета, без единиц: удобнее для арифметики, `px` дописывается в стилях.
- `defaultTextCps: 40` — черновое значение; настраиваемая скорость появится на этапе 6.
- `App` остался default-экспортом, как в шаблоне.
