# Этап 2. Ядро движка — контекст

Исходная спецификация — [../../02-engine-core.md](../../02-engine-core.md). Ход работ —
[progress.md](./progress.md). Этот файл — полная картина этапа на текущий момент.

---

## Цель

Типы команд, плоская программа сцены и интерпретатор с циклом interaction — чистые функции
над plain data, без React и MobX. Плюс `content/` с фабриками команд и линейной демо-сценой, и
`GameStore`, который держит состояние движка в MobX. Проверяется тестами: визуально на этапе
ничего не появляется, это осознанно.

Самый важный этап проекта: почти все решения из [разбора Ren'Py](../../../engine-research.md)
материализуются здесь.

## Где этап в роадмапе 0.1

- **Опирается на этап 1** (готов, PR #2): `RootStore`, `StoreProvider`, `useStores()`,
  экраны меню и игры.
- **Нужен этапу 3**: состояние кадра (`stage`) и текущая реплика — то, что рисует рендер;
  доступ к сторам из `features/` (приём `AppStores`).
- **Нужен этапу 4**: типы `choice` с блоками уже здесь; разворот блоков в программу и выбор
  варианта — там.
- **Нужен этапу 5**: состояние движка и есть снапшот сейва.

## Модель исполнения (зафиксирована в плане)

- Команды **мгновенные** (`scene`, `show`, `hide`, `music`, `sfx`, `set`, `jump`) и
  **требующие interaction** (`say`, `choice`).
- Цикл: применять мгновенные подряд до первой требующей interaction, на ней остановиться.
  Один клик = один проход до следующей такой команды. Это `run_context` Ren'Py и
  `Continue()` ink.
- Конвенции Ren'Py: `scene` очищает спрайты и ставит фон; `show` с тем же тегом **заменяет**
  спрайт; `hide` по тегу; позиции `left / center / right`; `ifChanged` у музыки.
- Сейв — снапшот состояния (позиция + переменные + кадр + музыка), не реплей. Загрузка —
  восстановить снапшот и выполнить одну команду на позиции.
- Переменные объявляются с дефолтами (`variableDefaults`), при загрузке
  `{ ...defaults, ...save.vars }`.

## Решения квиза этапа 2 (2026-10-09)

| # | Вопрос | Решение |
|---|---|---|
| 1 | Типизация id ассетов без зависимости `engine/` от `content/` | **Дженерик с дефолтом `string`**: `Command<I extends Ids = Ids>`. Движок и сторы работают с обычными строками, `content/` сужает: `type C = Command<ContentIds>` — опечатка в id становится ошибкой компиляции, параметр никуда не протекает |
| 2 | Как пишется сценарий | **Функции-фабрики** в `content/`: `scene('room')`, `show('anna', 'happy', 'left')`, `say('anna', '…')`, `narrate('…')`, `goTo('forest')`. Фабрика проверяет, что эмоция есть именно у этого персонажа |
| 2a | Рассказчик | Фабрика `narrate('…')`; в движке — `say` без `speaker` |
| 2b | Эмоция из реплики (`say('anna', 'sad', '…')`) | Позже и только в `content/`: фабрика развернётся в `show` + `say`, движок не меняется |
| 3 | Ветвление | **Оба механизма в 0.1.** Крупные ветки — отдельные сцены (`goTo`), короткие реакции — блоки внутри варианта выбора, после которых выполнение продолжается за развилкой. См. ниже |
| 3a | Запись перехода в другую сцену | **`goTo('forest')`**, а не голая строка: переходы — скелет сюжета, их должно быть видно и находить поиском |
| 3b | Внутреннее устройство блоков | **Разворот дерева в плоскую программу** при регистрации сцены, как указатели `next` у statement'ов Ren'Py. Позиция остаётся `{ sceneId, step }` |
| 4 | `call` / `return` | В сюжете будут, **но не в 0.1**. Позиция остаётся объектом, чтобы позже добавить `callStack` без ломки сейвов |
| 5 | Команды сцены кончились, `jump` нет | **Конец игры, возврат в меню** — как в Ren'Py при пустом стеке вызовов |
| 6 | Связь движка с MobX | **Чистое ядро**: функции над plain data, `GameStore` в `app/` держит состояние и вызывает движок. В `engine/` нет MobX |
| 7 | Доступ к сторам из слоёв ниже `app/` | **Приём как с темой**: в `shared/` — пустой интерфейс `AppStores` и `useStores()`, `app/` расширяет интерфейс своими сторами через `declare module` |
| 8 | Случайность в сюжете | **Не планируется** — генератор случайных чисел не делаем |

### Ветвление: как это пишется

```ts
choice([
  option('Пойти в лес', goTo('forest')),     // крупная ветка: уходим в другую сцену
  option('Остаться', [                       // короткая реакция: блок команд
    say('anna', 'Тогда подождём здесь.'),
  ]),
]),
say('anna', 'Темнеет...'),                   // сюда приходят все блоки-реакции
```

- `goTo('forest')` — сахар для блока `[jump('forest')]`. У движка одна модель: у каждого
  варианта есть блок, блок может закончиться переходом.
- Блоки вкладываются (внутри — свой `choice`), варианты можно смешивать.
- Вариант выбора: `{ text, when?, then: Command[] }`. Отдельный `set` у варианта не нужен —
  это обычная команда `set` в блоке.
- Тем же механизмом позже делается условный блок без развилки (`if` из Ren'Py).

## Решения по ходу (вопросы «доки» и «по факту»)

| Вопрос | Решение |
|---|---|
| Как Ren'Py защищается от бесконечного `jump` | Таймер: `check_infinite_loop` в `execution.py` бросает «Possible infinite loop», если скрипт долго идёт без interaction. Таймер нужен Ren'Py из-за произвольного Python в скрипте. У нас команды — O(1) операции над данными, поэтому **лимит шагов**: детерминирован и тестируется |
| Размер лимита | **10 000** мгновенных команд на один проход; ошибка называет сцену и шаг |
| Детерминированный ГСЧ | Не нужен — случайности нет (квиз, п. 8) |
| Где живёт `StageState` | В чистом состоянии движка; `GameStore` держит его целиком (квиз, п. 6) |

## Что входит

1. **Типы** (`engine/`): `Ids` с дефолтом `string`, `Command<I>`, `ChoiceOption<I>` с блоком
   `then`, `LocalizedText` + `resolveText()`, `requiresInteraction()`.
2. **Состояние и мгновенные команды**: `GameState` = `{ position, vars, stage, audio }`,
   `createInitialState()`, `applyInstant()` — чистые функции.
3. **Реестр сцен и программа**: сцена → плоская программа, реестр проверяет цели `jump` и
   стартовую сцену при регистрации, а не во время игры.
4. **Интерпретатор**: проход до interaction, `jump`, конец сцены = конец игры, лимит шагов.
5. **Контент**: id ассетов и персонажей, говорящие, `variableDefaults`, фабрики, линейная
   демо-сцена со всеми мгновенными командами.
6. **`AppStores` в `shared/`** — перенос доступа к сторам по приёму темы.
7. **`GameStore`**: держит состояние движка, «Новая игра» запускает демо-сцену, конец игры
   возвращает в меню.

## Что не входит

- Выбор варианта и разворот блоков `choice` в программу — этап 4 (типы — здесь).
- Рендер кадра и реплик, клик для продвижения — этап 3.
- Сейв в `localStorage`, валидация `zod` — этап 5 (здесь только тест, что состояние
  сериализуется в JSON без потерь).
- Аудио — этап 6 (здесь музыка — только поле состояния).
- `call` / `return`, метки, условные блоки, эмоция из реплики.

## Ограничения

- `engine/` не импортирует `content/`, FSD-слои и React — проверяет oxlint. MobX в `engine/`
  тоже нет (решение квиза, линтером не проверяется).
- Команды закрыты discriminated union: `switch` по `type` с `never` в default.
- Тесты — рядом с кодом (`src/**/*.test.ts`), а не в `tests/engine/`, как в спецификации:
  так решено на этапе 0.
- Код на английском, текст демо-сцены — на русском.

## Риски

- **Вариантность `when` в дженерике.** `when: (vars: ContentVars) => boolean` не присваивается
  `when: (vars: Record<string, VarValue>) => boolean` при `strictFunctionTypes` — контентная
  команда перестанет подходить под движковую. Лечится объявлением `when` методом
  (`when?(vars): boolean`, методы бивариантны). Проверить типовым тестом на шаге 1.
- **Сейвы и правка контента.** Плоская программа сдвигает номера шагов при любой правке
  сцены — старый сейв укажет не туда. Это вопрос этапа 5 (несовместимый сейв), здесь только
  фиксируем.
